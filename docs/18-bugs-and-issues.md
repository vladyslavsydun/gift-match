### 3–5. Issues: опис, умови виникнення, пріоритет

Кожен дефект я оформив як Issue на GitHub (вкладка *Issues → New issue*), мітка `bug` + мітка пріоритету.

Як я визначав пріоритет:
- **High** — ламає основну функцію або небезпечно;
- **Medium** — неправильні дані, але є обхід;
- **Low** — косметика, не заважає користуватися.

---

#### BUG-1. Вік приймає дробові числа

**Labels:** `bug`, `priority: medium`

**Summary:** Можна додати людину з дробовим віком (наприклад 25.5).

**Environment:** GiftMatch v0.2.0, Google Chrome, `npm run dev`, http://localhost:5173

**Steps to reproduce:**
1. Відкрити сторінку «Люди».
2. Ввести ім'я `Петро`.
3. Ввести вік `25.5`.
4. Обрати стать «чоловіча», професію `інженер`, хобі `спорт`.
5. Натиснути «Додати».

**Expected result:** Помилка «Вік має бути цілим числом від 1 до 120», людина не додається.

**Actual result:** Помилки немає, у списку з'являється «Петро, 25.5».

**Чому Medium:** дані неправильні, але програма працює, і користувач може відредагувати вік.

---

#### BUG-2. Пошук не знаходить людину, якщо регістр літер відрізняється

**Labels:** `bug`, `priority: high`

**Summary:** Пошук «оле» або «ОЛЕНА» не знаходить людину «Олена».

**Environment:** GiftMatch v0.2.0, Google Chrome, `npm run dev`, http://localhost:5173

**Steps to reproduce:**
1. Додати людину: `Олена`, 25, жіноча, дизайнер, хобі: малювання.
2. У поле «Пошук за ім'ям або хобі» ввести `оле`.
3. Очистити поле і ввести `ОЛЕНА`.

**Expected result:** В обох випадках у списку видно «Олена, 25».

**Actual result:** В обох випадках «Нікого не знайдено.» Знаходить тільки якщо ввести з великої літери як в імені («Оле»).

**Чому High:** користувачі зазвичай пишуть у пошуку маленькими літерами — пошук фактично не працює.

---

#### BUG-3. Ім'я з HTML-тегами показується як HTML

**Labels:** `bug`, `priority: high`, `security`

**Summary:** Якщо в імені є HTML-теги, браузер їх виконує замість того, щоб показати як текст.

**Environment:** GiftMatch v0.2.0, Google Chrome, `npm run dev`, http://localhost:5173

**Steps to reproduce:**
1. Ввести ім'я `<b>Тест</b>`.
2. Ввести вік `30`, обрати стать «чоловіча», професію `інженер`, хобі `кіно`.
3. Натиснути «Додати».

**Expected result:** На картці написано `<b>Тест</b>, 30`.

**Actual result:** На картці написано «Тест, 30» жирним шрифтом — теги зникли.

**Чому High:** це небезпечно. Замість `<b>` можна вставити `<img src=x onerror="...">` і виконати чужий JavaScript (це називається XSS). Особливо через імпорт JSON-файлу від іншої людини.

---

#### BUG-4. «Найпопулярніше хобі» при однаковій кількості

**Labels:** `bug`, `priority: low`

**Summary:** Коли кілька хобі зустрічаються однакову кількість разів, у статистиці показується тільки одне (перше за порядком додавання людей).

**Environment:** GiftMatch v1.1.0, Google Chrome, `npm run dev`, http://localhost:5173

**Steps to reproduce:**
1. Додати Петро (52, чоловіча, інженер, хобі: риболовля, автомобілі).
2. Додати Марія (67, жіноча, пенсіонер, хобі: садівництво, рукоділля).
3. Відкрити «Статистика».

**Expected result:** Показано, що всі хобі зустрічаються однаково (наприклад «риболовля, автомобілі, садівництво, рукоділля» або «—»).

**Actual result:** Показано тільки «риболовля».

**Чому Low:** це не заважає підбору подарунків, просто статистика неточна. Залишив у Backlog.

### 6. Виправлення помилок

Кожну помилку виправляв в окремій гілці `fix/...`.

**BUG-1** (`fix/bug-1-age-decimal`) — `isNaN` пропускав дробові числа. Замінив на `Number.isInteger`:

```ts
// було
if (isNaN(data.age) || data.age < 1 || data.age > 120) {
// стало
if (!Number.isInteger(data.age) || data.age < 1 || data.age > 120) {
```

Додав автотест: «дробовий вік (25.5) - помилка (BUG-1)».

**BUG-2** (`fix/bug-2-search-case`) — `includes()` порівнює з урахуванням регістру. Тепер обидва рядки переводжу в нижній регістр:

```ts
const q = query.trim().toLowerCase();
...
return this.people.filter(
  (p) => p.name.toLowerCase().includes(q) || p.hobbies.some((h) => h.toLowerCase().includes(q))
);
```

**BUG-3** (`fix/bug-3-html-in-name`) — картка будувалась через `innerHTML` з ім'ям як є. Додав функцію `escapeHtml()` у новий файл `src/utils.ts`, яка замінює `<`, `>`, `&`, `"`, `'` на безпечні послідовності:

```ts
export function escapeHtml(text: string): string {
  return text
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
}
```

і використав її в картці: `${escapeHtml(p.name)}`. Додав 2 автотести на `escapeHtml`.

Коміти:
```
fix BUG-1: вік приймав дробові числа (25.5)
fix BUG-2: пошук не знаходив людину, якщо регістр літер відрізнявся
fix BUG-3: ім'я з HTML-тегами показувалось як HTML (додано escapeHtml)
```
