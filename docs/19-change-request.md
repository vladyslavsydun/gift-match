# Практична робота №19. Зміна вимог та супровід програмного забезпечення

## Мета

Показати процес внесення змін до вже розробленого програмного продукту.

## Хід роботи

### 1. Нова вимога

Після демонстрації версії 1.0.0 з'явилась нова вимога (від «замовника» — викладача / знайомих, які тестували програму):

> «Програма пропонує подарунки за 5000 грн, а в мене є тільки 1000. Хочу вказати бюджет, щоб бачити тільки ті подарунки, які можу собі дозволити».

Оформив як User Story:

**US-11.** Як користувач, я хочу вказати бюджет для людини, щоб бачити тільки подарунки, які вкладаються в цю суму.

**Acceptance Criteria:**
1. **Дано** форма, **коли** я залишаю поле «Бюджет» порожнім, **тоді** людина зберігається, і підбір працює як раніше (бюджет необов'язковий).
2. **Дано** людина з бюджетом 1000 грн, **коли** натискаю «Підібрати подарунок», **тоді** всі подарунки мають ціну ≤ 1000 грн.
3. **Коли** ввожу бюджет 10 або 200000, **тоді** бачу помилку «Бюджет має бути цілим числом від 50 до 100000 грн».
4. **Тоді** на картці людини і в заголовку рекомендацій написано «бюджет до 1000 грн».
5. **Коли** жоден подарунок не вкладається в бюджет, **тоді** бачу «На жаль, нічого не знайдено.» і «Спробуйте збільшити бюджет.»
6. **Коли** редагую людину і стираю бюджет, **тоді** бюджет зникає.

**Функціональна вимога FR-15:** Користувач може вказати необов'язковий бюджет (ціле число 50–100000 грн). Якщо бюджет вказаний, у рекомендаціях показуються тільки подарунки з ціною ≤ бюджету.

### 2. Аналіз впливу на систему

Питання, які я собі поставив:

| Питання | Відповідь |
|---|---|
| Чи треба змінювати формулу балу? | Ні. Бюджет — це **фільтр**, а не ще одна характеристика з коефіцієнтом. Інакше подарунок за 5000 при бюджеті 1000 все одно міг би бути в топі. |
| Що буде зі старими даними в localStorage (без бюджету)? | Поле необов'язкове (`budget?: number`), тому старі записи працюють без змін. |
| Що буде зі старими файлами експорту? | Імпортуються як раніше, бюджет просто відсутній. |
| Чи потрібні нові екрани? | Ні, одне поле у формі. |
| Ризики | Можна зламати редагування і імпорт — треба перевірити регресійно. |

### 5. Внесення змін у програму

Гілка `feature/budget`.

```ts
// recommender.ts
// Якщо в людини вказаний бюджет - дорожчі подарунки не показуємо.
export function recommend(person: Person, gifts: Gift[], limit = 5): Recommendation[] {
  return gifts
    .filter((gift) => person.budget === undefined || gift.price <= person.budget)
    .map((gift) => scoreGift(person, gift))
    .filter((r) => r.score > 0)
    .sort((a, b) => b.score - a.score)
    .slice(0, limit);
}
```

### 7. Перевірка існуючого функціоналу

**Нова функція вручну** (Олена, 25, жіноча, дизайнер, малювання + фотографія, бюджет 1000):

| Перевірка | Результат |
|---|---|
| Картка | «дизайнер · жіноча · бюджет до 1000 грн» ✅ |
| Рекомендації | Скетчбук і маркери (900 грн) 91%, Штатив для телефону (500) 77%, Фотоальбом ручної роботи (700) 77%, Набір акварельних фарб (550) 71%, Ароматична свічка (350) 55% — всі ≤ 1000 ✅ |
| Бюджет 10 | «⚠ Бюджет має бути цілим числом від 50 до 100000 грн» ✅ |
| Бюджет 50 | «На жаль, нічого не знайдено.» + «Спробуйте збільшити бюджет.» ✅ |

Без бюджету в топі Олени був «Графічний планшет» за 2500 грн (91%) — з бюджетом 1000 його вже немає, як і має бути.

**Регресійна помилка, яку я знайшов.** Коли я відредагував Олену і **стер** бюджет, на картці все одно залишилось «бюджет до 1000 грн». Причина — у `update()` нові дані «накладались» на старий запис:

```ts
// було
this.people[index] = { ...this.people[index], ...data };
```

Якщо в `data` немає поля `budget`, то залишається старе. Виправив — беру тільки нові дані, а зі старого запису лише `id` і `createdAt`:

```ts
// стало
const old = this.people[index];
this.people[index] = { ...data, id: old.id, createdAt: old.createdAt };
```

Після виправлення бюджет стирається правильно ✅. Добре, що я перевірив редагування окремо — до цього `update()` працював правильно, бо всі поля були обов'язкові.

**Регресія старих функцій:** повторно пройшов усі 20 тест-кейсів з практичної №15 — всі PASS.
