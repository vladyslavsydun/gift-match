# Практична робота №9. Основи Git та GitHub

## Мета

Ознайомитися із системами контролю версій та навчитися працювати з Git і GitHub.

## Теорія коротко

**Git** — система контролю версій. Вона зберігає історію всіх змін у файлах проєкту, і можна будь-коли подивитися, що змінилось, або повернутися до старої версії.

**GitHub** — сайт, де зберігаються Git-репозиторії в інтернеті. Там можна поділитися кодом, працювати разом, робити Pull Request.

Основні поняття:
- **репозиторій** — папка проєкту з історією змін;
- **коміт (commit)** — «знімок» змін з коментарем;
- **гілка (branch)** — окрема лінія розробки;
- **remote** — віддалений репозиторій (на GitHub).

## Хід роботи

### 1. Встановлення та налаштування Git

Встановив Git з сайту git-scm.com. Перевірка:

```bash
git --version
# git version 2.43.0
```

Налаштував ім'я та пошту (вони підписують кожен коміт):

```bash
git config --global user.name "Ваше Ім'я"
git config --global user.email "your.email@example.com"
git config --global init.defaultBranch main
```

### 2. Створення репозиторію

Створив локальний репозиторій у папці проєкту:

```bash
mkdir gift-match
cd gift-match
git init
```

На GitHub створив порожній репозиторій **gift-match** (кнопка *New repository*, без README, бо README я створюю сам) і підключив його:

```bash
git remote add origin https://github.com/[ваш-логін]/gift-match.git
```

Посилання на репозиторій: **https://github.com/[ваш-логін]/gift-match**

### 3. Створення .gitignore

Файл `.gitignore` каже Git, які файли не треба зберігати. Мені не треба зберігати:
- `node_modules/` — бібліотеки, вони встановлюються командою `npm install` і займають багато місця;
- `dist/` — результат збірки, його можна зібрати знову;
- логи і налаштування редакторів.

```gitignore
# залежності
node_modules/

# результат збірки
dist/

# логи
*.log
npm-debug.log*

# налаштування редакторів
.vscode/
.idea/
.DS_Store
```

### 4. Створення README

`README.md` — це «обличчя» репозиторію, GitHub показує його на головній сторінці. Спочатку я написав коротко: назву, опис і статус «у розробці». Потім README доповнювався (див. практичну №20).

### 5. Основні команди: clone, add, commit, push, pull

```bash
# додати файли в "чергу" на коміт
git add README.md .gitignore

# створити коміт
git commit -m "Initial commit: README та .gitignore"

# відправити на GitHub (перший раз з -u, щоб запам'ятати гілку)
git push -u origin main

# забрати зміни з GitHub (наприклад, якщо редагував README на сайті)
git pull

# скопіювати репозиторій на інший комп'ютер
git clone https://github.com/[ваш-логін]/gift-match.git
```

`git status` показує, які файли змінені і ще не закомічені — я використовував її постійно.

### 6. Перегляд історії змін

```bash
git log --oneline
```

Перші коміти мого репозиторію:

```
docs: додано звіти практичних 1–8 (vision, вимоги, діаграми, прототип)
Initial commit: README та .gitignore
```

Також корисна команда з графом гілок:

```bash
git log --oneline --graph --all
```

А `git diff` показує, що саме змінилось у файлах до коміту.

### 7. Створення гілки

```bash
# створити гілку і одразу перейти на неї
git checkout -b feature/project-structure

# подивитися всі гілки
git branch

# повернутися на main
git checkout main
```

У гілці `feature/project-structure` я зробив початкову структуру проєкту (практична №11), а потім злив її в `main`:

```bash
git checkout main
git merge --no-ff feature/project-structure
git push
```

Я використовую `--no-ff`, щоб в історії був окремий коміт злиття і було видно, що зміни прийшли з гілки.

### Правила, які я для себе прийняв

- `main` — завжди робоча версія;
- кожна нова функція — в окремій гілці `feature/...`, виправлення помилки — `fix/...`, документація — `docs/...`;
- коміт — одна логічна зміна з зрозумілим коментарем українською.

## Результат

Налаштований GitHub-репозиторій з `README.md`, `.gitignore` і першими комітами.

## Висновок

Я навчився основам Git: створювати репозиторій, робити коміти, відправляти зміни на GitHub і створювати гілки. Тепер вся історія проєкту зберігається, і я можу повернутися до будь-якої версії.
