## Хід роботи

### 1–2. Kanban-дошка та інструмент

Інструмент: **GitHub Projects** (вкладка *Projects* у профілі → *New project* → шаблон *Board*). Плюс у тому, що дошка в тому самому місці, що й код, і задачі можна зв'язати з Issues і Pull Requests.

Посилання на дошку: **[вставити посилання на GitHub Project]**

Колонки дошки:

| Колонка | Що означає |
|---|---|
| **Backlog** | всі задачі, які колись треба зробити |
| **To Do** | задачі поточного спринту |
| **In Progress** | роблю зараз (не більше 2 одночасно — це WIP-ліміт) |
| **Review / Test** | зроблено, треба перевірити |
| **Done** | перевірено і злито в `main` |

Додаткові поля в GitHub Projects: **Priority** (High / Medium / Low), **Sprint** (Sprint 1…4), **Estimate** (сторі-поінти).

### 5. Пріоритети

Пріоритети взяті з MoSCoW (практична №4): Must → **High**, Should → **Medium**, Could → **Low**. Помилки з ручного тестування отримують пріоритет за серйозністю (див. практичну №18).

На дошці в колонці **To Do** картки відсортовані за пріоритетом — зверху High.

### 7. Розподіл задач

Я працюю один, тому **Assignee** у всіх задач — я. Але навіть одному корисно ставити себе виконавцем: на дошці фільтр *Assignee: me* показує тільки мої задачі, і в команді це було б так само.

Як рухається картка: **To Do → In Progress** (створюю гілку) → **Review / Test** (відкрито Pull Request, перевіряю) → **Done** (злито в `main`). У GitHub Projects це можна автоматизувати: в *Workflows* увімкнути «Item closed → Done» і «Pull request merged → Done».

Підсумок по спринтах: усі 4 спринти закрито, всі 11 User Stories в колонці **Done**, BUG-1…BUG-3 закриті, BUG-4 залишився в Backlog з пріоритетом Low. Після спринтів, під час підготовки до захисту, знайдено BUG-5 (однаковий відсоток у подарунків, High) — його картка пройшла To Do → In Progress → Review / Test → Done, виправлено у версії 1.1.1.

## Результат

Backlog + Kanban-дошка в GitHub Projects + 4 спринти.

## Висновок

Kanban-дошка допомагає бачити весь проєкт одразу: що зроблено, що зараз і що далі. WIP-ліміт (не більше 2 задач у роботі) допоміг мені не розпорошуватись. Навіть для однієї людини це корисно, а для команди — просто необхідно.
