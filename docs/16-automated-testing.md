# Практична робота №16. Автоматизоване тестування

## Мета

Ознайомитися з принципами автоматизованого тестування та реалізувати перші автоматизовані тести.

## Хід роботи

### 1. Функції, які доцільно тестувати автоматично

Автоматично найпростіше тестувати **«чисті» функції** — ті, що отримують дані і повертають результат, без HTML і без localStorage. У моєму проєкті це:

| Функція | Файл | Чому варто тестувати |
|---|---|---|
| `scoreGift()`, `recommend()` | `recommender.ts` | головна логіка продукту, легко помилитися у формулі |
| `validatePerson()` | `validation.ts` | багато правил і граничних значень |
| `buildMarketplaceUrl()` | `marketplaces.ts` | від посилання залежить заробіток (партнерська мітка) |

Інтерфейс (кнопки, форма) я тестую вручну (практична №15).

**Інструмент:** [Vitest](https://vitest.dev/) — працює разом з Vite і розуміє TypeScript без налаштувань.

```bash
npm install -D vitest
```

У `package.json`: `"test": "vitest run"`.

### 5. Аналіз результатів

Перший запуск — **один тест упав**:

```
 ❯ tests/recommender.test.ts (7 tests | 1 failed)
   × recommender > бал завжди від 0 до 100
     → expected 109 to be less than or equal to 100
 ✓ tests/validation.test.ts (5 tests)
 ✓ tests/marketplaces.test.ts (2 tests)

 FAIL  tests/recommender.test.ts > recommender > бал завжди від 0 до 100
AssertionError: expected 109 to be less than or equal to 100
 ❯ tests/recommender.test.ts:51:26
     50|     expect(result.score).toBeGreaterThanOrEqual(0);
     51|     expect(result.score).toBeLessThanOrEqual(100);
       |                          ^

 Test Files  1 failed | 2 passed (3)
      Tests  1 failed | 13 passed (14)
```

**Що сталося:** бал вийшов **109%**. Я подивився формулу для хобі:

```ts
hobbyScore = 0.6 + 0.2 * matched.length;
```

- 1 збіг → 0.8 ✔
- 2 збіги → 1.0 ✔
- **3 збіги → 1.2** ✘ — оцінка більша за 1!

Тоді бал = 0.45 × 1.2 + 0.25 + 0.20 + 0.10 = 1.09 → 109%. Вручну я цього не помітив, бо в каталозі майже немає подарунків з трьома хобі, і в моїх тестових людей було по 2 хобі.

### 6. Виправлення помилки

Обмежив оцінку максимумом 1:

```ts
// 1 збіг = 0.8, 2 і більше збігів = 1.0 (більше 1 бути не може)
hobbyScore = Math.min(1, 0.6 + 0.2 * matched.length);
```

Повторний запуск:

```
 ✓ tests/recommender.test.ts (7 tests)
 ✓ tests/validation.test.ts (5 tests)
 ✓ tests/marketplaces.test.ts (2 tests)

 Test Files  3 passed (3)
      Tests  14 passed (14)
```

Коміти:
```
Автотести: recommender, validation, marketplaces (1 тест падає - бал більше 100%)
fix: оцінка за хобі не може бути більше 1 (бал був 109% при 3 збігах)
```

> Пізніше тестів стало більше: при виправленні дефектів (практична №18) я додав тести на BUG-1, BUG-3 і BUG-5, а при зміні вимог (практична №19) — тести на бюджет. Зараз їх **26** у 4 файлах, і всі проходять.

## Результат

Набір автоматизованих тестів (Vitest), які перевіряють алгоритм підбору, перевірку даних і посилання на маркетплейси. Тести знайшли реальну помилку в алгоритмі.

## Висновок

Автотест знайшов помилку, яку я пропустив при ручному тестуванні. Тепер після кожної зміни я запускаю `npm test` і за пів секунди знаю, що нічого не зламалось. Я зрозумів, чому логіку краще тримати окремо від інтерфейсу — так її легко тестувати.
